# 彼方 · Kanata｜P1–P7 连贯开发与验收计划 v3

> **当前有效、面向连续执行的唯一阶段放行标准**（2026-10-28）。P0 已完成静态源码与设计资料审查；P1–P7 均未实现/未通过。本文覆盖 [docs/plan.md](plan.md) 内 2026-10-27 旧 Kanata v4→v5 迁移验收段落以及 [原技术设计](20261027-kanata-technical-design-v1.md) 的 P0 停止提示；保留历史原文用于审计，不修改 raw/。阿拜多斯预设细节以 [五人预设规格](20261028-kanata-abydos-preset-spec-v1.md) 为准，安全架构以根目录 [AGENTS.md](../AGENTS.md) 与 [架构接口规范](../架构接口与Agent开发说明书.md) 为准。
>
> 用户希望 **一个 AI Agent 任务连续执行 P1→P7**。每阶段通过后立即继续，不因正常阶段边界反复请求批准；真实个人数据擦除、危险破坏操作、Git 强推/合并 main/发布或事实不可确定的产品关键取舍依然需要当次明确授权。**不能以“之前决定永久废弃旧聊天”解释为现在允许触碰真实设备文件。**

## 0. 资料优先级、版本和产品边界

1. 以当前用户决策 D01（旧「温馨小家」业务数据不迁入新彼方、未来受控清理）及 D02（五人阿拜多斯预设）为最新产品约束；保留其他业务模块数据。旧 main 上 chat v4 及完整备份 v12 是**现有源码事实**，不是必须迁移旧聊天的产品要求。
2. 当前执行入口：本计划 v3 → [预设规格](20261028-kanata-abydos-preset-spec-v1.md) → [v2 变更](20261028-kanata-clean-start-and-abydos-preset-v2.md) → [完整需求清单](../raw/完整需求清单.txt) → 2026-10-27 的 P0 源码分析/问题与历史规划。发生冲突时仅用明确的较新决策覆盖对应旧条款，**别扩大为删减其他需求**。
3. 目标现有 Vue3 + Pinia + Vite + Capacitor Android/Web + DeepSeek，保持单体、保留 protectedModules/backupParticipants/restoreCoordinator/主密码/通知及所有其他生活模块。禁止 Python 常驻服务、无评估 SQLite 迁移、强行接管整个应用数据层。
4. 不迁移旧小暖聊天、记忆、事件和关系；旧 chat v1–v4 单项备份禁止作为彼方导入；旧 v1–v12 全备仍应安全恢复**非 chat 部分**，在明确兼容适配前拒绝高风险部分恢复。
5. 单一世界含多角色，原始角色卡版本和世界实例数据分离；世界外不得窜访、共享记忆、角色知识或现实数据；现实三权限 read / remember / share 默认拒绝（如用户未显式授权）。
6. 禁止伪造已发生世界事件、历史消息、官方原作剧情或离线时实时发言；无背景 AI 常驻承诺；默认原文保留，事件修改有因果追溯。

## 1. 单次长任务的工程运行协议

**每阶段统一五件套：** 前置依赖 → 小批量修改 → 定向/负向/故障测试 → 至少两轮独立自查并修复 → 阶段证据与放行判定。

- 开始：读 AGENTS、架构规范、最新 docs、当前仓库源码、git status/HEAD/diff。严格只在 **Kanata** 开发；检查远端是否变化，不能丢弃用户未提交文件。历史记录不能当新测试结果。
- 先形成阶段 checklist 与测试列表；将任务拆成可运行垂直切片，不要一次性生成 50 个类。变更关联 `contracts.d.ts`、负向类型案例、模块注册、设置、备份、深链、Android 生命周期的实际接口。
- 每个 P 实施后至少进行 **两轮自查**：①架构/数据/权限/异常路径 ②按需求清单+预设验收逐项核对，发现错误立即修改并重新运行相关测试。两轮不能只是两句“已检查”。
- 所有业务接口修改运行 `npm run check`；涉及原生/数据恢复/加密/通知/设备才附加对应测试。无设备时明确标为 **BLOCKED/NOT RUN**，不能凭编译结果宣布 Android 验收完成。
- 每阶段在 docs/ 记录：目标文件、实际改动、用例编号、命令与退出码、覆盖与未覆盖、审查修正记录、剩余风险、Git diff/状态、Go/No-Go 判定。定向测试与总测试均真实运行才可以标 PASS。
- **Go**：本阶段所有安全关键、必须验收实际通过且前置依赖完成，就自动进入下一个 P；**No-Go**：测试失败、数据损毁/安全不确定、需要实机而环境缺失或其他阻塞，先修复；无法解决时记录准确阻塞并终止依赖它的后续阶段，不得跳过门禁伪装全案完成。
- 在 Kanata 可按用户运行当次授权进行普通 Git commit 作为阶段检查点；不得默认推送、强推、创建 PR、合并 main 或发布。未经额外授权不得对真实用户设备执行旧数据清理或读取真实私人备份。
- 真实 API Key、密码、私人数据不得进仓库/日志/测试；使用合成数据。异步响应重试、权限撤销、应用页面销毁与过期任务必须检查上下文 revision 后才能写回。
- 深度思考与连续执行由运行 Agent 的可用时间/上下文/工具限制决定；不能声称未实际运行的后续阶段已完成。任务被中断时记录 checkpoint 以便在新会话续作。

## P0：已完成的基线（非新功能）

**输入：** ForMyself `main` 静态基线。**产物：** 既有 P0 源码核对、两次技术设计、v2 决策与本 v3 计划。**验收：** docs 与 Git diff/来源可追溯、无原仓库业务改动。本项目 P0 已按文档审查完成，但 v3 本身不是新功能测试证据。

## P1：纯领域模型与契约（必须先通过）

**前置：** P0、源码与需求复核，无旧数据内容迁移要求。
**实现：** World、Card+Version、CharacterInstance、WorldPreset、Conversation、Message、LorebookEntry、Memory、Relationship、WorldEvent+Effect、BackgroundTask、LifeGrant 以及 WorldUserIdentity；严格世界归属、稳定引用、版本校验、实例化纯函数和类型声明。没有真实文件 I/O、UI、联网。
**必须验收：**
1. 同一基础卡在两个世界生成不同实例，所有记忆/关系/时间水位独立；不能创建跨世界群成员、来源引用或关系边。
2. 五人预设数据的结构校验：五个唯一人物条目、五实例、五私聊、一群聊、世界书条目与初始关系引用均合法。
3. 重复 seed 操作的逻辑结果一致；随机/当前时间只由显式注入 factory 提供，禁止隐藏不可重现状态。
4. 非法角色身份、重复 ID、孤儿引用、未知未来 schema 版本等有明确拒绝与错误码；不得先用旧 chat v4 normalize 剥掉新字段。
5. 无旧小暖迁移类、无业务写入；新增单元/边界/负向类型测试通过，`npm run check` 通过。

## P2：新数据仓库、旧聊天清理协议与备份恢复

**前置：** P1 已通过。**实现：** 新加密数据命名空间与可注入 Repository、正确 ready/restore 写保护、读失败保全、串行恢复任务与失败重试、主密码重加密、chat 全量/单项备份契约及设置页适配、旧 warm-home 清理协调器；不删其他模块。
**必须验收：**
1. 文件不存在/版本不兼容/解析或解密失败/主备均损坏/写队列失败五类分别可观察；失败绝不能以空新世界覆盖原数据。
2. 合成旧数据：明示确认前 0 删除；确认后仅移除白名单旧主/tmp/bak、旧恢复键及旧通知；多次清理、任意中断、二次进入都能完成且不误删其他存储。
3. 即使清理中断，新的五人 seed 不能重复，旧 chat watch/计时器不会重新写回旧文件；清理必须在受保护会话与恢复协调器安全状态下执行。
4. v1–v12 完整旧备份中非 chat 模块逐项可恢复，旧 chat 被识别、预览、明确丢弃且不能复活；旧 chat 单项备份得到明确拒绝。
5. 新 Kanata 世界/卡原文/头像/群聊/记忆/事件/授权备份往返无损；失败回滚、主密码改密与受保护会话/内存清理可验证。
6. 测得 Web/Android 数据增长基线；如全量 JSON 不满足后续真分页/目标指标，明确门禁并在后续实施必要存储方案，而非标完成。关键测试与 `npm run check` 通过。

**警戒：** 旧聊天永久删除只是要实现的功能，不允许本次 Agent 在用户真实手机或真实备份上执行测试删除。

## P3：真实可用的五人预设、世界管理、角色卡与世界书

**前置：** P2 的安全读写与清理测试通过。
**实现：** [详细五人预设](20261028-kanata-abydos-preset-spec-v1.md)、版本化 manifest、五张可追溯角色定义、世界书、十组队内基本关系、五个私聊与一群聊的 seed、创建/复制/归档世界、SillyTavern 常见 PNG/JSON 角色卡导入与安全未知字段保留。
**必须验收：**
1. 空档首次初始化，精确计数：**世界 1、角色实例 5、私聊 5、群聊 1、长记忆 0、真实消息 0、已发生事件 0**；重复进入/中断恢复后三次结果不增。
2. 五人核心人格与世界书不少于八条；结构/官方事实来源审核、非官方内容标识及版权审查记录；不打包官方头像/完整台词。
3. JSON/PNG 的声明支持格式正确解析，非法 chunk/扩展/超大文件清楚报错；原数据与可保留扩展可安全往返。
4. 卡更新不会覆盖正在游玩的实例经历；同卡跨世界创建实例、世界书知情权限/预算和用户身份替换验证通过。
5. 无 API Key 可浏览预设但不发送假对话、不触发无授权计费；涉及 UI/导航/备份/加密的回归与 `npm run check` 通过。

## P4：私聊/群聊、发言决策、DeepSeek 和使用统计

**前置：** P3 seed 真正持久化可用。
**实现：** 多会话 UI、真实 speaker IDs 与 @、群聊动态发言门控、私聊即时响应与可配置延迟、两种聊天风格、气泡分组、AI 上下文过滤、按 attempt 的 Token 及 RMB 估算、read 权限基础。
**必须验收：**
1. 五人私聊分别稳定，群聊 @白子优先但其他角色可沉默；不同 assistant speaker 不混合；不会模型一轮无上限自相循环。
2. 同时切换世界/会话、Abort/Retry、过期响应不得写错目标；隐私和角色知识范围正确，先判断授权再组织上下文。
3. 普通与 RP 模式切换不清人格与关系；用户连续短句合理合并，单轮角色/气泡数有上限。
4. 流式、非流式、超时失败/回退/截断重试的 usage 与真实/估算/缺失标注正确，每个 attempt 仅记一次；价格版本来源标注，API Key 永不落日志/业务事件。
5. 五人角色质量验证（对话呈不同风格、能有分歧、不强制恋爱、不知道未公开私聊）；`npm run check` 和必要 UI/原生回归通过。

## P5：L0–L4 记忆、因果事件、关系与现实生活授权

**前置：** P4 多人会话及权限门禁可用。
**实现：** 原文、情节摘要、长期记忆事实、事件状态分层；去重提取任务与来源 revision；角色有向关系/情绪、世界事件候选/规则 Effects/撤销重建；生活模块 per-world+instance+module 的 read/remember/share 三独立权限；角色绑定。
**必须验收：**
1. 重复消息/任务重试不增加重复记忆；摘要失败保留 L0 与旧有效摘要；源消息修订/删除使相关派生项 stale/needsReview。
2. AI 不直接修改事件/关系真值；撤销 E1 后不覆盖独立 E2 的 effects；依赖不明时阻断并要求人工决定；世界书静态设定与后生经历明确分层。
3. 未授权角色不能读取现实日程/心情/体重/财务等；记住与分享分别检查独立权限；撤权能阻止新读取、后续自动传播并处理旧衍生信息。
4. 全局/模块覆盖角色与失效绑定不按同名意外重选；跨世界和角色私人知识漏斗测试全部通过。
5. 记忆编辑、冲突、来源追溯、因果撤销 UI 测试及完整备份恢复/ `npm run check` 通过。

## P6：自主虚拟生活、角色社交、通知与视角

**前置：** P5 事件提交与权限链可用。
**实现：** 可选自主世界模拟、日程与共享地点约束、角色之间的独立会话、前台恢复补算、主动私聊/延迟、通知、普通/上帝视角。
**必须验收：**
1. 时间同步 1:1；同窗口重试、跨日、跨时区、时钟倒退不会重复写世界事件；水位仅成功持久化后前进。
2. 自治关闭期间不补算；重开从当前时间起；每日 0 场不会创建角色间完整对话但可保存轻量事件，任务量/费用有技术上限。
3. 群聊和私聊/自主事件不同步不矛盾：不重复演出同一事件，角色日程/地点冲突由代码验证。
4. 自治、角色主动联系、本地通知三个开关独立；免打扰与通知拒绝有效；离线过期提醒不集中补发/不伪造发送时间。
5. 普通视角不显示未经分享的角色私人聊天，上帝视角只授权**用户管理查询**，绝不使 NPC 获得全知权限；Android/Web 各自验证生命周期限制。

## P7：综合容量、恢复、权限和可交付验收

**前置：** P1–P6 的所有强制门禁均通过。
**实现：** 端到端合成数据回归、旧备份矩阵、强制停止/中断恢复、主密码改密/安全、容量压测与真分页/归档、UI 适配、Android/Web 验证、权限与版权复查。
**必须验收：**
1. [完整需求清单](../raw/完整需求清单.txt) 第十五节 15 场景逐项记录 PASS/FAIL/BLOCKED/NOT RUN，另加 [预设规格](20261028-kanata-abydos-preset-spec-v1.md) 的专项场景和旧聊天清理专项测试。
2. 1k/10k/100k 消息等合成数据测试冷启动、保存、索引检索、真实分页、备份/恢复/改密时间与峰值内存；与事先确定的设备阈值比较，不得凭 UI 显示前 100 条声称支持分页。
3. `npm run check`、相关 Android 构建与设备测试、Web E2E、安全/权限/备份回归真实执行；没有真机就明确记录局限/阻塞，不能宣称全链路已通过。
4. Git 差异/原始资料/未提交用户改动保护，README/契约/设置/测试/版本文档同步更新；未解决安全或数据一致性风险为 No-Go。
5. 输出总验收矩阵、实测命令与结果、提交记录、截图/日志（仅合成数据）、剩余风险与未实现功能清单。**不自行合并 main、发布正式安装包或删除用户真实旧数据**。

## 9. 尚未冻结的参数及安全默认

- 新数据格式版本、应用存储切片、预设版本同步/删除与旧全备过滤适配的细节交由对应 P 用测试验证，**不能悄悄更改平台加密协议**。
- 模型上下文预算、每日自治数、AI 用量/重试上限、等待时间等，在没有用户明确数值时应采用**保守、可配置、不隐性计费、不自动分享**的临时默认，在文档标「工程默认，待确认」；涉及不可逆或安全选择停在阻塞点。
- 官方 IP 预设若缺少可分发授权：实现文本配置与合成的替代数据作为测试夹具、标记发布阻塞，不能擅自打包官方图片或对外声称商业/公开分发许可已获确认。
- 涉及设备上真实历史聊天删除，只能**开发流程并用合成数据测试**，用户首次使用还需在应用内明确确认；开发任务授权不等于主动触发真实擦除。
