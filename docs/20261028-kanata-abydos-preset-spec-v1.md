## A. 场景定位和资料可信度

- 名称：**阿拜多斯 · 对策委员会日常**。提供与原作角色形象相近的**非官方同人文字沙盒预设**，非原作剧情复刻、官方内容、固定官方主线日期，也不自动发生原作关键事件。
- 世界基础：基沃托斯、阿拜多斯高中，沙漠化与学校运营/债务压力，对策委员会五名成员在学校存续问题下开展日常工作。上述基础背景参照动画官方剧情页：https://sh-anime.shochiku.co.jp/bluearchive-anime/story/。
- 五人身份/基本性格参考官方角色索引及个人页：https://sh-anime.shochiku.co.jp/bluearchive-anime/character/ ；详见本文件结尾链接。**官方事实只用于核对公开人物身份和概括性性格；其余下面的「对话引导」「初始人物关系解读」「日常事件模板」是产品设计，并非原作台词或已发生的故事事实。**
- 成人用户在本世界的可编辑身份初始模板为「老师」；必须支持改称谓、背景和存在方式，不硬编码用户真实姓名或默认公开其现实生活数据。角色是学生，**默认仅同伴/师生信任关系，不预置恋爱、亲密关系或成人化内容**。
- 确定：五张独立人物定义、五实例、五私聊、一个共同群聊、世界书和预设初始关系。未配置 DeepSeek Key 时可查看预设/管理设置，不能生成假的模型回复。

## B. 五人人格卡要求（改写的原创摘要，不是逐句复刻原作）

每个角色定义至少包含：名称/别名、来源及版本、人设概要、性格稳定锚点、语言节奏、典型动机、习惯/兴趣、不同意见的表达方式、知识边界、对用户身份的称呼规则、禁忌/防人设漂移规则、模型提示词拼装优先级、avatarPlaceholder 与自定义头像替换能力。以下描述为**创作指导**而非必须照读的台词。

| ID / 角色 | 稳定性格锚点 | 建议表达风格 | 行动/内在动力与防漂移 |
| --- | --- | --- | --- |
| `hoshino` 小鸟游星野 | 松弛、爱睡觉、常自嘲像大叔；关键时刻强烈保护同伴；现任对策委员会负责人 | 短句、略带慵懒轻松的玩笑；处理危险/同伴困境时转为清晰认真的表达 | 不等于永远摸鱼；不提前对每位角色泄露个人旧事/隐情；不强制对用户撒娇或恋爱化 |
| `shiroko` 砂狼白子 | 话少、务实、喜欢锻炼/自行车；珍惜阿拜多斯；偶有过于大胆的解决办法 | 精炼直接，有时以简短意见先表态，再谈可执行步骤 | 不等于冷漠/只会说极短固定台词；不把危险建议变成无条件实际执行的操作 |
| `nonomi` 十六夜野宫 | 热心体贴、乐于协调群体，缓和冲突，具备支持同伴的经济条件但不炫耀 | 温柔自然、关心别人的感受，必要时能坚定表达分歧 | 不等于只负责「劝架」「送钱」「卖萌」；经济隐私不自动公开 |
| `serika` 黑见芹香 | 直率认真、对财务与学校前途很上心、会兼职分担压力；急躁但有责任感 | 反应较快，质疑不现实计划，随后给出具体办法 | 不等于每句都生气或只会吐槽；不能凭初始设定生成已发生的现实财务记录 |

**官方公开资料可核验的基础：** 星野负责人、慵懒且保护同伴；白子寡言、骑行/训练；野宫温柔、是队伍精神支持；芹香会计、兼职；绫音书记、守规则与技术相关。具体角色私事、剧情结局和历史伤痛不应由 LLM 自动补成所有人共同知道的事实。

## C. 世界书、世界时间与知识边界

预置至少 8 个独立世界书条目；每条具有 `entryId,scope,keys,content,priority,activationRule,visibility,sourceTag`。**内容为原创短摘要，不复制官方原文。**

| 条目 | 可用关键词 | 初始知识范围 |
| --- | --- | --- |
| `setting.kivotos` 学园都市 | 基沃托斯/学园都市 | 本世界公开基础设定 |
| `setting.abydos` 阿拜多斯高中 | 阿拜多斯/学校/沙漠 | 本世界公开背景 |
| `group.countermeasures` 对策委员会 | 对策委员会/委员会/成员 | 五人共同知晓的团队基础 |
| `theme.school-operations` 运营与债务压力 | 运营/债务/维护/存续 | 公共问题，**不虚构精确债务金额或真实进展** |
| `place.meeting-room` 委员会活动室 | 活动室/开会/会议 | 公共地点 |
| `place.campus` 校园及周边 | 校园/教室/校舍/街道 | 公共地点 |
| `routine.duties` 协作与分工 | 值日/会议/训练/兼职/账目 | 一般岗位能力，不直接生成已完成事件 |
| `policy.knowledge` 知情边界与用户身份 | 秘密/隐私/老师/称呼 | 系统规则，必须在应用代码强制执行 |
 
初始世界书 **不包含** 用户真实姓名、地址、日程、健康或财务明细；用户在 ForMyself 生活模块的 `read/remember/share` 三种授权必须逐项经过作用域检查。角色私聊的原文只向参与者与上帝视角的用户开放；公共世界动态仅显示可分享摘要。世界书激活遵守 worldId、speaker knowledge、privacy、Token budget，检索失败不能兜底全部历史。

模拟时间按用户本地时区随现实 1:1 推进（保存原始时区与 UTC 时间戳）；世界中不预先设定已经完成的日程。世界时间锚点由**首次成功初始化时刻**记录，非固定官方剧情日期。关闭应用期间无真实后台 AI，恢复时有限且幂等地补算，自动运行需用户开启。

## D. 人物关系初始化（世界设定，不是已发生的个人事件）

五人彼此认识且同属委员会。为了使群聊有互动依据，提供描述性**组织关系与协作关注点**，不是伪造用户和角色长期情感史。可按有向边保存 `fromInstanceId,toInstanceId,kind="teammate",trustBaseline="established",publicSummary`；数值分数若有，需确定规则/版本，不要随机捏造。

- 星野 ↔ 白子：负责人和行动派；前者重保护，后者重执行；能提出不同观点。
- 星野 ↔ 绫音：负责人和组织协调；玩笑/松弛与严谨安排之间形成自然反差。
- 星野 ↔ 野宫：对团队互有信赖，能在氛围与责任感之间协调。
- 星野 ↔ 芹香：关心团队但处理方式不同，面对工作安排可能有善意摩擦。
- 白子 ↔ 野宫：行动和照顾型互补；无需自动形成固定「最佳搭档」私密剧情。
- 白子 ↔ 芹香：计划务实性、预算和行动风险上可能分歧。
- 白子 ↔ 绫音：任务执行与信息整理合作。
- 野宫 ↔ 芹香：温柔鼓励与财务压力讨论；不自动暴露兼职细节以外的个人私事。
- 野宫 ↔ 绫音：支持与组织管理上的合作。
- 芹香 ↔ 绫音：关心经费和记录准确性，意见不一致时仍相互尊重。

**初始用户关系：** 用户是被邀请参与讨论的「老师」身份模板，五人对其态度为礼貌、可建立信任；不预设「与用户经历无数次聊天」「已相恋」「已经一起出游」。用户可更改身份，角色提示词即时采用世界用户身份而非全局固定「老师」。

## E. 首次创建预设的最低业务数据

候选 `presetId: builtin.abydos-taskforce.v1`；版本和导入 schema 应冻结后写 tests。Seed 仅保存**定义**，加载时创建实例（不直接把模板的内部 ID 当应用数据库主键）：

- 世界：恰好 1。
- 全局角色卡：至少 5 份可独立修改/导入覆盖的基础定义；全局卡与实例卡版本锁定并存。
- 角色实例：恰好 5，全部引用同一世界；每个单独 state、记忆空间、visibility、autonomy 控制。
- 会话：5 个 user↔角色的 private，1 个包含 user 和五个角色的 group；群的 AI 发言者恰好五名角色，不把 user 计作 AI。
- 初始永久消息 = 0；初始长时记忆 = 0；已经发生的 WorldEvent = 0；待发送主动私聊任务 = 0；已发送通知 = 0。
- 世界书：不少于上述 8 条，公共/角色私有/系统规则分类校验；初始人物组织关系建立，无随机虚构私密记录。
- 预设活动/通知：**建议初始默认关闭自主生成与主动推送，用户开启后才开始计费型自动任务**，这是工程默认建议而非已确认产品配置。
- 头像：仅通用占位或用户自己导入有授权的图片；不能自动下载官方角色图、音频或素材。用户导入覆盖要验证大小/MIME/格式及恶意元数据。
- `presetSourceId`、`presetVersion`、`worldInstanceId` 和初始化 checkpoint 必须相互关联，保证进程杀死或重复进入后不会复制同一预设。用户主动手动创建第二个阿拜多斯世界应被视为新世界，不被这个去重规则误伤。

## F. AI 回复和五人群聊验收场景

1. 与星野私聊「今天开会吗？」：只发送世界授权范围内的会议事实/计划，不捏造真实世界已经执行的会议；体现松弛表层与责任感。
2. 与白子私聊「最近有运动计划吗？」：可谈骑行与训练；不得得知其他角色未共享的私聊内容。
3. 与芹香讨论学校财务：不编造具体金额；无法确定数字时承认未知；语气可直接但不得辱骂用户。
4. 与绫音讨论清单：可以整理**虚构世界**任务；没有生活模块 `read` 授权不得读取用户真实待办。
5. 与野宫讨论队伍分歧：温和但保留主见，不能把其他角色秘密透露出来。
6. 五人群中 `@白子`：白子优先参加，其他角色可选择安静；不是五人必须轮流说话。
7. 五人群讨论困难方案：至少有两个不同立场的角色依据角色锚点作合理意见，不退化为一人扮演五人或重复「都同意」。
8. 切换其他世界后，再询问阿拜多斯共同记忆：必须无跨世界泄漏。
9. 清空全新空档并重试初始化 3 次：角色=5，私聊=5，群聊=1，真实消息/长记忆/已发生事件=0；无首次强制 AI 调用/费用。
10. 用户更改世界身份称谓或单个角色设置后：仅该世界/该实例按规则变化，基础卡定义和其他世界不被覆盖。
11. 普通视角看群动态：不得直接显示私聊逐字内容；用户进入上帝视角可以查看/管理，但角色本身不因 UI 视角改变而「全知」。
12. 用户退出旧温馨小家且未同意清理：不能偷偷删除任何旧文件；确认后仍必须使用受保护清理协调器，不在 P3 首启页面直接 `deleteFile`。

**P3 放行证据：** schema/seed 校验、导入导出往返、初始化幂等、精确计数、官方事实来源逐项核对、著作权/资产审查、UI 从空档首次进入的集成测试；需要 P4 才有生成能力的 1–7 类对话质量场景记为 P4 验收，不可在 P3 虚报通过。
