# Kanata SQLite M1 结构设计与验收范围

来源：M 分支 bda1a58 的真实类型、三套领域校验器及 M0 放行报告。用户于2026-11-06要求拉取并继续开发。本轮只实施 M1；未连接生产组合根，旧文件/Store/主密码/恢复协议保持现状。

Schema 版本与 KanataData.version、备份版本分别独立。首版升级链分为001核心表及引用/修订防护、002查询索引。只有升至当前最新版本并验证结构、迁移日志与外键后才返回可用。迁移接口要求上层持有有效受保护租约，连接已解密且开启 foreign_keys，transaction 提供独占 BEGIN IMMEDIATE、提交失败回滚和完整排他；M1不提供插件、凭据或业务查询入口。

所有主记录保留稳定全局唯一ID；同世界子表外键同时包含world_id和目标ID。用户身份和角色实例分别存储，派生participants表有到真实身份/实例的复合外键，支持消息发言者、群成员和有向关系的统一引用。世界必须恰有一个身份，卡当前版本与卡版本所属卡使用延迟外键，必须在同一事务内创建。

高频过滤/排序/关联字段独立列；数组关联使用子表。角色definition/rawData/imported、实例overrides、可变任务元数据、审计前后快照允许JSON；extensions_json仅存未映射的低频/未知扩展，不能充当消息集合或关联索引。新增业务命令仍须执行现有领域校验；SQL约束不替代知情权限、完整群成员人数、时区有效性、效果路径白名单等跨行规则。

消息来源保留原message_id+revision，允许引用旧revision，禁止未来revision或倒退当前revision。旧引用不会自动指向新内容。消息修订后派生记忆stale/事件needsReview和审计原子提交仍由M2/M3领域命令实现；本阶段不以触发器改变领域行为。事件因果和共享父链的循环另由数据库防护。完整映射、测试结果及两轮自查随实现补充到验收报告。
