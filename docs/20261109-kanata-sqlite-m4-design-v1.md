# Kanata SQLite M4 技术设计 v1

2026-11-09，北京时间。对应 [访问矩阵](20261109-kanata-sqlite-m4-preflight-v1.md) 与 [任务书](20261109-kanata-sqlite-m4-task-v1.md)。以下是设计契约，实施状态以验收报告为准。

## 访问路径

组合根持有 M2 候选实例并注入当前世界/会话 scope 及候选 Runtime。聊天 ViewModel 复用消息窗口，消费显式的 `loadConversationView` / `readMessages` 操作。仅保留当前会话标题、模式、revision、群回复设置、当前世界名称/归档状态、成员名摘要、消息窗口、引用、错误和在途状态。生产分支继续使用 legacy Store。候选不实例化 legacy Store，也不读取 legacy 备份或归档。

会话概览使用 scope 的独立投影，角色按成员记录分页查询名称，不展开卡版本 raw/import/图像。候选用量按会话计数及有界页，按需展开。列表更新使用 Repository CAS，页面发布已提交 DTO；错误保留可重试状态。历史定位复用 M2 keyset 和按 ID 查询，不用临时全库搜索。其他领域用 M3 Repository 的显式命令、scope 和单 ID 查询，缺口增加受固定目录约束的 SQL。

群聊成员变更采用产品确认的方案 1，空群原地编辑，有消息时按新名单创建同世界独立会话并保留原群。完整契约见 [Completion 设计](20261109-kanata-sqlite-m4-completion-design-v1.md#群聊成员变更)。

## 资源与失效

| 缓存 | 上界及保留期 |
| --- | --- |
| 聊天消息 | 50 条每页，100 条活动会话窗口。旧页和新页使用同一 scope 的 cursor，切换清空 |
| 引用 | 1 条当前会话摘要，引用切换与 scope 失效清除 |
| 会话、世界 | 当前各 1 条摘要，已知字段投影；同 scope 重读替换 |
| 成员与用量 | 各最多 50 条一页，替换页；用量详情关闭清除 |
| 世界、角色、世界书、记忆、事件和任务管理 | 每个可见列表最多 50 个摘要，关闭、切页、切世界或撤权清除。正文按 ID 一次只保留当前详情 |
| 运行时 | 每活跃会话最多 1 个回复 Controller 和 1 个延迟任务轮询；取消后校验 owner，外部 provider 忽略 abort 也不能发布 |

页面 owner 绑定 scope、generation、受保护 session revision。连接失效独立发布 generation，所有 Store 消费者同步清除明文、取消请求、停止轮询。重开必须经过候选租约。读失败保留显式 error，不发布 ready。恢复门禁、后台、锁定与 dispose 优先使 owner 失效，再等待原生事务完成或回滚。旧 scope 的对话框与计时器不能操作新 scope。

## 领域等价和证据

- 消息保留 M2 审计、派生失效、CAS、群聊 speaker、历史锚点、引用与延期。AI 上下文只获取本会话所需消息，独立读取关系、记忆、事件、世界书及授权。知识排序需保留原优先级、并列次序、激活条件和预算；不能用截断第一页替代。对有意跨批的动作执行前后检查 owner，批次处理完即释放。
- 记忆和事件优先用现有来源证明与授权查询。管理权限和角色正文读取单独表达。事件预览确认、审计和 Effects 走原有事务。自治计划按原水位与回执运行，任务失败回滚。
- 组合根保留 legacy 备份、恢复、改密和旧 Web 协议。合成候选不提供生产迁移、全备、恢复或改密。001–004 冻结，默认激活位 false。
- 在真实 SQLite harness 捕获 SQL、参数 scope、返回行数和事务结果。对实际 Runtime 在受控用例观察对象序列化和克隆、故意延迟查询后切 scope，并比较 1k/10k 两档数据。使用新建 Windows/WHPX API 34 AVD 执行真实 JS→Native→SQLCipher，记录 APK、SQL catalog、数据集指纹与错误/重测日志。

## 编码前两次自审

1. 安全与资源。基线候选恢复门禁变化不会同步清除所有聊天引用。明文残留反例包括晚到查询、同时切世界与读取引用、后台后重入。单卡的原始导入载荷可远大于展示名字，成员展示须 SQL 级投影。未见既有群成员人数上限，成员不能依赖回复数上限证明有限。
2. 业务与兼容。群聊参与者与回复角色上限不同。分页不得使后页成员失去 @ 能力。候选必须保留实际 Vue 群聊和 character 只读语义；世界归档、事件预览和恢复保留现有含义。明确分别证明旧 Web、Android 合成候选及普通 Android 打包门禁。基线检查与这两次设计审查不算最终两轮实现自检。

## 当前实现与未关闭的设计项

- 会话由候选 Runtime 注入。ViewModel 使用 `shallowRef` 持有一个会话摘要、一个世界摘要、最多 50 个成员或用量条目和最多 100 条当前消息。历史面板打开时隐藏聊天时间线，额外持有当前检索页最多 50 条，关闭即释放。历史搜索按 scope 和 keyset 读取，每次最多 32 个 50 行批次。用量页关闭后清空。世界工作区持有当前一页最多 50 条摘要，切换 tab 清空上一页，授权页最多七个模块。
- 群聊通过角色名、别名、兴趣的 50 项投影流式评分，保留原提及歧义规则和最多 8 位候选。聊天不从卡片的原始导入资产或头像读取正文。已完成回复只查最多 32 个 ID、revision 和 senderId。当前聊天历史最多 40 条，事件提示最多 12 条。关系显示投影受上下文的 64 KiB 最大预算约束。
- 世界书与记忆保留精确预算排序。角色授权先于正文，按 50 项分页取候选。按字节成本分桶，每个桶最多保留 `floor(4000/cost)` 项。较低排名的同成本条目在这些条目均已处理后无法放入预算。世界书候选正文的保守上界是 16 MB，记忆排序桶只保留 ID 和分数，正文与来源按最终 ID 读取。此上界是设计约束，设备探针测量的是行数、调用次数和 ViewModel 保留条数。
- 消息和延期任务同事务保存。失败或源 revision 变化拒绝提交。会话设置和待执行活动回复的加速同事务。SQLite 自治计划按世界分批计算签名，完成时依照现有英文排序轮换选出最多 8 个角色，再分别读取日程；窗口回执、事件、效果和水位继续同事务。历史 001–004 不需要改动。
- 受保护的候选会话世代、请求 scope 及 owner 在每个业务 SQL 前后复核。显式释放、锁定、后台及恢复门禁撤销现有请求。角色授权 UI 成功变更时释放候选连接，旧 AI、页面及角色引用失效。
- 工作区的世界书、记忆、事件、自治任务目前只有摘要列表。卡片编辑、完整的事件确认/撤销交互、记忆整理与来源交互、世界书编辑、全局角色绑定及其生活模块消费、自治完整设置、旧历史自动整理的候选等价入口仍需实施。深层记忆和事件溯源中的临时关联集合还需独立的增长和权限复核。
