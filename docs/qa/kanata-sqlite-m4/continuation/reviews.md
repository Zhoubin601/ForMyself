# M4 续作的两轮反例复核（检查点）

这两轮按任务书分别执行。现有证据不足以把任一轮标为“全范围通过”。结论为 BLOCKED。v2 历史自检保留在 [Completion QA](../completion/reviews.md)。

## 第一轮：安全、权限、Repository、事务与暂存

| 反例 | 实际结果、处置和证据 |
| --- | --- |
| 空群编辑并发首条消息；归档或软删后看起来为空；另建事务 COMMIT 失败 | 正式群聊命令在事务中检查未过滤消息元数据、scope、预期 revision 与命令回执。主机红测、修复与 [Android 复测](r3-confirm-result.txt)；取消不建群、失败回滚、重试仅一群。 |
| 大量同目标 Effects、预览后插入他人 Effects、已提交事务重放 | 旧重放反例见 [红测](r3-replay-red.txt.gz)。改为有界 keyset、原顺序与基线重放；冻结 Effects 证明发生变化时旧预览拒绝。[主机](r3-replay-host.txt) 和 Android 执行集合、拥有者及审计；旧兼容撤销接口仍有累计选择集合。 |
| 宽记忆来源和深宽混合；尾部 revision 变化；未获授权的角色 | [主机 SQLite](r4-growth-host.txt) 的 1k/10k 单次最多 50 行、授权正文 1，尾部 revision 不符时正文 0。分享接收方授权不足时零正文投影，使用事务内 SQL 复制。初次设备增长超时，保留 [原始失败](r4-device-result.txt)；分档返回后有复测。 |
| scope 在两个异步读之间变化；对话框关闭后迟到确认 | 组件测试验证切换角色不会启动旧来源读取，关闭账本不发送迟到撤销命令，见 [Vue](r6-management-vue.txt.gz)。候选组合根逐次 SQL 之前、之后复核会话与页面 owner。所有 A–G 页面、批次中断和消费者的等价实测仍缺。 |
| 普通聊天取用宽来源记忆；旧兼容入口 | 调用链 `kanataSqliteChatRuntime.readPromptKnowledge → memories.readFor → readMemory` 仍组装已选记忆的全部来源引用，随后提示词序列化 `sourceRefs`。旧 `listFor`、`listManaged`、`share` 和保存也组装完整 DTO；事件兼容上下文仍有关系展开。不能把普通消息窗口的 1k/10k 测量当成这条路径通过。后续须在不改变提示词和 provenance 语义的情况下关闭。 |
| 关系图规模与审计 | 单批 SQL 行数不等同于 JS 堆峰值，也不证明事务或 native SQLite 内存有界。确认集合的摘要提供提交复验，但断点恢复、每批取消后的查询数、全宽事件集合与逐 Effect 审计均未完整测量。 |

## 第二轮：产品、UI 等价、平台和证据

| 反例 | 复核结果 |
