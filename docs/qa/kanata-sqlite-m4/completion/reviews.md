# M4 Completion 自检记录

此页保留 v2 自检。R0–R8 续作的反例与复测见 [新检查点复核](../continuation/reviews.md)。

## 第一轮　访问、权限、并发

- 将 1k/10k 条消息作为同一回复链的反例。旧实现逐条过桥并在 JS 保留 ID，定向测试失败。改为 SQLite 核对归属、版本和终点，再按授权元数据翻页。复测两档都是 2 次查询，循环在读取正文前拒绝。
- 将共享记忆末端标为过期，检查无权路径的 SQL 投影。复测两档授权都只读取当前正文，拒绝时正文读取数为 0。首轮为共享链强制选用部分索引，SQLite 报 `no query solution`。移除该 hint，保留受 scope 约束的连接顺序。原始失败和定向重测均保留。
- 向同一祖先插入两条汇合路径，验证分页去重并拒绝异世界、异方向续页。插入循环边由现有约束拒绝。真设备逐页复核返回计数。
- 审查仍存在的全量关联。旧事件撤销使用集合和重放数组，兼容读写可累积完整来源 DTO。相关完整宽扇出、混合关系和取消增长矩阵未关闭。

## 第二轮　产品等价、平台与证据

- 建群使用既有作用域与成员类型验证，测试跨世界成员拒绝、顺序和命令回执。历史群成员编辑在旧源码明确归独立策略，现有资料缺少对旧消息权限的口径，已提出需要确认的问题。
- 全局生活角色绑定测试区分继承和明确不选，旧 revision 拒绝，归档世界只让绑定不可用。卡片历史和详情分开读取，发布仍使用不可变版本与 CAS。原生文件选择发生真实后台切换后的续接仍待验。
- 设备首次复跑在工作区超时，后续为场景加阶段定位，再跑身份、世界书、旧聊天和 M3 事务。最终 APK 结果以 QA 的受测目录和指纹为准。完整流程包含但不限于角色同步、记忆整理、事件撤销、联系社交、生活角色消费者和历史整理，这些流程仍未达到全范围自检。

原生选择控件反例。完整 check 对新增绑定范围的 `select` 按现有 WebView 门禁报错。替换为带标签的单选组，保持显式无绑定与继承的区别。见 [定向复测](evidence/ui-feedback-retest.txt)。


## 2026-11-10 后续产品决策补记（保留历史原文）

第二轮自检中“历史群成员编辑权限口径待确认”是当时的真实审查记录，不删除、不改写。随后用户已明确确认方案 1，并于提交 `e296b2c5dd082f35b95c943bd838e3fe6a506357` 将规则写入 Completion Design、Preflight、M4 设计和 GROUP-01–05 QA：

- 空群允许原地编辑，保留 conversation ID。
- 有历史时保留原群，按新名单另建同世界独立会话；新群从空历史开始。
- 原群消息、引用、成员及既有访问语义不变；新群不能通过搜索、定位、引用或角色上下文读取原群历史。
- 归档或软删除但仍保留的消息也算历史；提交时在事务内复核消息存在性、revision、scope 和 owner。
- 并发首条消息要求重新确认另建；取消、失败不得修改原群或创建半成品；重试必须幂等。

该产品决策已解决。当前阻塞是实际成员编辑入口、Repository 原子分流、GROUP-01–05 完整测试及 Android E2E，不再是产品语义待确认。现有 createGroup 隔离测试不得冒充完整成员编辑验收。
