# M4-R 复核记录

两轮分别按安全与事务、产品与平台审阅当前检查点。以下记录包括 A–G 的仍缺链路。两轮均未达到 MR8 的全范围验收完成条件。

## MR2-G4 第一轮 权限与事务

- 用 1,000 和 10,000 个独立角色的生活授权建立共享给当前角色的合成来源。一条消息同时进入历史、记忆提示词和事件上下文。核对消息直属引用的世界、会话和 revision，区分聊天读取与记忆、事件、自治的记忆授权。
- 复测发现普通发送用于决定上一位发言者的查询会把撤权助手正文交给 JS，即使提示词随后正确排除。改用仅含 ID、revision、时间、状态和发送者的投影。两个宽样本撤权后的正文读取均为 0。
- 审查 append CAS、受保护租约与临时工作表。历史根在写事务内复核。原工作表行只存在于内存 SQLite，落库、顺序提示、关系写入和清理在同一事务。主机注入写入失败后消息及临时表均消失，同命令重试和重放保留原始标签顺序。
- 后台任务在权限前置阶段按页校验来源。结果引用通过任务 ID、世界、消息 ID 和精确 revision 查验。兼容任务 DTO 仍会聚合，相关故障覆盖不能替代该缺口。
- 现有候选页面关闭、锁屏和 owner 切换仍由租约守卫。专用迟到 provider 探针取消后查询和写入均为 0。各故障的设备覆盖范围见本轮报告。

## MR2-G4 第二轮 兼容、性能与取证

- Android 首轮原生统计显示 10k 回复已经写入 10,001 条规范化标签，旧 QA 的逐行比较在 420 秒截止。改用 SQL 一次比较完整有序 JSON，保留原超时日志。随后的撤权探针发现上一位发言者正文读取并复修。
- 原生计时另显示旧提示校验语句一轮约 48.6 秒。先在 SQL 内物化有限根、只为含数组提示的消息扫描关系，并按消息主键匹配。主机同一测试由约 101.5 秒降到 9.5 秒。此项的 Android 结果与普通 APK 指纹另列。
- 逐条对照旧标签属性顺序与去重后，1k/10k 样本分别精确匹配 2,002 和 20,002 条有序标签。主机旧归档 oracle 在 1k/10k 两档分别匹配 798 和 9,798 个归档 ID，证据只针对嵌套精确引用样本。
- 兼容审查仍发现 eventFromRow、insertEvent、commitEvent、旧 preview/revoke/correct、消息兼容 DTO 和 loadTask 的物化入口。不透明编码扩展、完整旧导出和全故障矩阵待补。两轮 MR2 检查均有反例与复测记录，G4 仍 BLOCKED。

## MR2-G4 事件来源第一轮 · 权限、数据与事务

- 检查输入标签 → 消息引用 → 因果事件的访问次序。主机宽样本用两个公开事件参与角色，按旧 Map oracle 校验首次位置、末次值、末尾标签和规范化行。owner、世界及 revision 错误、撤权前置判定和正文读取为零均有定向断言。
- 主机首次 SQL 审计在事件 revision 更新前写入，触发 KANATA_INVALID_AUDIT_REVISION。修正为 CAS 更新、插入审计、落库标签，再应用 Effect，保持同事务；撤销、修正、窗口回执和失败回滚复测通过。
- 破损提示测试初次误将 userId 当作 participant ID，触发外键拒绝。改由合成 participants 表读取真实 participant ID 后，重复、缺失、多余及 null 四项均在提交前拒绝，revision 与 Effects 保持原值。
- 单次真实故障结果与尚未覆盖的世界/锁屏/设备复合矩阵见验收 v2。旧兼容读取与历史字符串 action 仍可能物化完整对象。

## MR2-G4 事件来源第二轮 · 兼容、平台与边界

- 对照候选事件台的实际字段访问及旧兼容消费者。提议/提交新回执仅为 ID，旧事件/审计输出的返回契约保留。候选普通修正流式验证来源并在 SQLite 复制关系，不在 Runtime 或 Store 重组 Event。
- 前三次 AVD 的边界断言失败均保留。带诊断的第三次报告 50 行查询、50 条暂存，但 Effect 重放行同时带 recorded_at 和 extensions_json，被误计为完整 Event。复测分类加入事件正文列 summary，同时保留查询、暂存、对象及回执独立断言。
- 逐项标注完整读取、特殊历史 JSON、深链和宽扇出混合写入、每档独立 PSS/RSS 与真实页面生命周期的证据边界。两轮记录覆盖本次事件切片，G4 和 MR2 仍 BLOCKED。

- 最新候选 APK 的 1k/10k 定向及综合回归均成功，APK 指纹一致。两档完整顺序的设备 SHA-256 与离线夹具 oracle 相同。普通 APK 默认门禁和冻结 checksum 已复核。

## 2026-11-11 事件读取第一轮 · 权限、完整性与兼容

- 逐一核对 readFor、四类关系、Effect、Audit 和 JSON chunk 的权限与游标身份。角色视角先验权，管理视角沿用受保护 World Runtime。关系提示验证必须在 SQLite 内完成，块读取不把大成员当成无引用。
- 历史 action 以空串、ASCII、BMP、代理对、孤立 surrogate、混合串、null、数组、对象和缺失分别与旧 materializer 对照。UTF-16 JS 回退保留，普通 JSON chunk 使用 code point 定位原始编码文本。
- 确认 legacy.revoke 的旧世界签名和 caller 集合逐页精确比较，临时 SQL 选择表与旧 receipt 在同事务。明确后代先于 uncertain 的审计生成顺序保留。
- 审计种子首次因 revision 重叠拒绝，关系测试首次因 fixture 已有关系重复而拒绝，均修正夹具并复测。旧字段的完整输出仍可在 legacy 中显式物化。
