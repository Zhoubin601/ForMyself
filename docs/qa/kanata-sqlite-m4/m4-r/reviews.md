# M4-R 复核记录

两轮分别按安全与事务、产品与平台审阅当前检查点。以下记录包括 A–G 的仍缺链路。两轮均未达到 MR8 的全范围验收完成条件。

## 第一轮 权限、数据与事务

| 范围 | 反例与检查结果 |
| --- | --- |
| A | 世界状态与群编辑有独立 CAS。静态复制缺候选事务，尚无法验证映射、失败重试及源数据隔离。 |
| B | 卡片发布以当前版本 CAS，导入工作区仍需验证系统选择器挂起时的 lease 和大对象清理。 |
| C | 角色预览走授权的 Repository。knownBy 详情仍一次读出，完整读者规模、并发游标与关闭清理待验。 |
| D | 1k/10k 不同源角色、授权和回复链证明均在 SQL 内。撤销一项授权后，两种读取入口的正文和标签均为 0。提示词收集与跨组确认未覆盖。 |
| E | 基线 10k 在 audit 写入中超时，证据包括原生 query plan。索引约束修复后，在 128 条审计已写但尚未提交处强停，重开原事件、审计及回执全部回滚。同计划复用后逐项审计和持久回执通过。旧预览与修正仍有完整闭包。 |
| F | enqueue 来源先验证消息 revision 和会话，再验证 SQL 授权。无绑定角色的任务拒绝有生活标签的来源。窗口强停回归和租约检查不能覆盖缺失的消费者。 |
| G | 历史整理签名覆盖会话、revision 和集合，保留已规范化关系。旧扩展中的非规范化引用无完整检测证据。 |

MR2 定向夹具的早期主机探针先遇到角色实例必填字段缺失，随后发现继承了原测试消息 revision=2 和旧授权。补齐合成实例必填字段，显式使用 revision=1 的合成消息并重新挂载本轮标签。最后调整探针以区别 memory 与 message 的标签查询。最终 5 项主机 SQLite 定向和 Android 两档定向证据见 QA 入口。

## MR2-G4 第一轮 权限与事务

- 用 1,000 和 10,000 个独立角色的生活授权建立共享给当前角色的合成来源。一条消息同时进入历史、记忆提示词和事件上下文。核对消息直属引用的世界、会话和 revision，区分聊天读取与记忆、事件、自治的记忆授权。
- 复测发现普通发送用于决定上一位发言者的查询会把撤权助手正文交给 JS，即使提示词随后正确排除。改用仅含 ID、revision、时间、状态和发送者的投影。两个宽样本撤权后的正文读取均为 0。
- 审查 append CAS、受保护租约与临时工作表。历史根在写事务内复核。原工作表行只存在于内存 SQLite，落库、顺序提示、关系写入和清理在同一事务。主机注入写入失败后消息及临时表均消失，同命令重试和重放保留原始标签顺序。
- 后台任务在权限前置阶段按页校验来源。结果引用通过任务 ID、世界、消息 ID 和精确 revision 查验。兼容任务 DTO 仍会聚合，相关故障覆盖不能替代该缺口。
- 现有候选页面关闭、锁屏和 owner 切换仍由租约守卫。专用迟到 provider 探针取消后查询和写入均为 0。各故障的设备覆盖范围见本轮报告。

## MR2-G4 第二轮 兼容、性能与取证

- Android 首轮原生统计显示 10k 回复已经写入 10,001 条规范化标签，旧 QA 的逐行比较在 420 秒截止。改用 SQL 一次比较完整有序 JSON，保留原超时日志。随后的撤权探针发现上一位发言者正文读取并复修。
- 原生计时另显示旧提示校验语句一轮约 48.6 秒。先在 SQL 内物化有限根、只为含数组提示的消息扫描关系，并按消息主键匹配。主机同一测试由约 101.5 秒降到 9.5 秒。此项的 Android 结果与普通 APK 指纹另列。
- 逐条对照旧标签属性顺序与去重后，1k/10k 样本分别精确匹配 2,002 和 20,002 条有序标签。主机旧归档 oracle 在 1k/10k 两档分别匹配 798 和 9,798 个归档 ID，证据只针对嵌套精确引用样本。
- 兼容审查仍发现 eventFromRow、insertEvent、commitEvent、旧 preview/revoke/correct、消息兼容 DTO 和 loadTask 的物化入口。不透明编码扩展、完整旧导出和全故障矩阵待补。两轮 MR2 检查均有反例与复测记录，G4 仍 BLOCKED。
