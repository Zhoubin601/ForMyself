# M4 两轮实现自检

## 第一轮　访问、安全、并发

| 反例 | 处理与复测 |
| --- | --- |
| 在同一角色开始读取后切换世界，或恢复门禁在原生查询返回前变化 | 原实现只有候选连接和事务末尾复核。现每条业务 SQL 前后检查候选世代、scope 和租约，ViewModel 同步清空。定向晚到页/引用反例、Android 快切、锁屏、恢复门禁零业务访问及撤权场景见 [定向](evidence/directed-final.txt) 和 [设备结果](evidence/android-final-result.txt)。 |
| 延迟任务关联表写失败，或者活动回复加速失败 | 源消息与任务写入改为同事务，配置与加速也改为同事务。主机在真实 SQLite 注入具体语句失败并检查原 revision、任务和可重试结果。新增消息后重放旧请求会得到 `STALE_TURN`。 |
| 恶意跨世界或跨词复用游标，稀疏搜索在扫描上限之前没有命中 | scope 和标准化检索词绑定游标。搜索返回已检查边界，续页不跳过未检查历史。测试 Unicode NFKC、32 次查询、续页和两种拒绝。 |
| 固定预算下高优先级条目在下一页，或低价条目越过超预算条目 | 保留精确排序所需的成本桶候选。以 20 组混合成本、并列排序和大于一页的样本与原贪心结果对照。1k/10k 两档在主机和真机桥跟踪行数和对象序列化。 |
| 未授权的事件、关系状态或记忆通过元数据旁路读取正文 | 事件/记忆预筛角色和可见性。事件摘要、关系动态维度及记忆正文在来源授权后读取。M3 授权负例继续运行，M4 额外用忽略取消的合成模型测试撤权迟到。 |

## 第二轮　产品语义、兼容和证据

| 反例 | 处理与复测 |
| --- | --- |
| 角色群聊分页后漏掉 @、回复顺序被历史窗口打乱，或 character 可以手动发送 | 复用角色提及和消息窗口规则，按页累计命中和歧义，保留气泡顺序与引用。设备 Vue 场景实跑群聊、失败重试、滚动锚点、历史定位、延期、character 拒绝和锁定。 |
| 自治按 SQLite BINARY 轮换导致角色顺序与原产品不一致 | 自治从有界批次选出相同的 `localeCompare('en')` 顺序窗口，使用含大小写和标点的 321 角色样本及绕回对照。设备 M3 窗口故障、强停重开、回执和水位回归继续运行。 |
| 设备回归使用了上次的 APK 或丢失合成隔离 | 首次复跑遇到旧 AVD 进程退出，保留 [连接失败](evidence/android-scoped.txt)。新建独立 API 34 AVD 后核验三方包为空和安装读回 SHA。普通构建单独核验包名、BuildConfig、页面与 SQL catalog。 |
| 新作用域使用重复变量名，导致 strict 失败 | [原始 TypeScript 失败](evidence/type-permission-prefilter.txt)保留。修正事件摘要投影局部绑定名，最终复跑两套类型检查和 `npm run check`。 |
| 把摘要列表和已有 M3 命令当作所有管理 UI 的等价实现 | 实际核对发现工作区仍缺完整世界书/记忆/事件操作、角色卡和部分自治/设置交互。已将缺口分别列入验收。当前两轮检查覆盖已实施切片，完整 M4-6 门禁仍待完成。 |
