# P7 加密历史分页格式与失败边界

本增量基于实际 P6 仓库及 P7 容量诊断，不引入数据库或服务，不改变主密码、安全凭据、AES 密文协议或恢复协调器。只在用户显式整理历史时转换；不主动清理真实设备旧聊天。

## 存储与接口

- 原主/tmp/bak 路径和 recovery key 不变。普通数据仍 `kanata-data/version:1`。首次归档后头文件为 version:2，新增 `messageArchives`；旧版本应用会明确拒绝 version:2，防止把残缺历史当完整资料导出。
- 每页最多 50 条完整原消息，页类型 `kanata-message-page/version:1`，在 `formyself/kanata-pages-v1/<ciphertext-SHA256>.enc`。沿用 CryptoJS OpenSSL salted passphrase AES；散列是加密头内的完整性/文件标识，不宣称改变为 AEAD。
- 加密头中每页含世界/会话、原消息 ID/revision/createdAt、有序元数据、密文字节数、4096 位 Bloom 索引。索引记录 NFKC+小写的 1–4 字符片段，只用于排除不可能命中的页；最终匹配必须解密正文精确比较。索引不赋予角色任何知识权限。
- `Store.archiveHistory/readHistory/activateHistoryMessage` 及 `prepareBackup/backupSnapshot` 是受保护 Store 门面。仓库可注入同一个文件系统。查询最多返回 50 条，按时间/ID稳定排序；统计实际页与字节。游标绑定世界、会话、查询和数据代次；变更后必须重新查询。预算耗尽明确失败，不返回会跳过未经检查页的游标。

## 引用闭包、提交与恢复

只归档早于最近 200 条且未被记忆/事件/任务/审计等引用的完整回复连通组件。一个组件超过 50 条则保留。来源原文继续位于活跃图，引用版本和普通/上帝权限不变。用户从历史修订时先验证并将完整一页重新激活，再使用原修订/事件失效规则。

先写不可变新页并读回校验，之后提交主图。验证前失败仍保留完整旧主图；主图保存失败保留引用已验证页的最新草稿与现有密文恢复记录，重试不丢消息。load 先校验头和逐页 stat；正文按需校验散列/形状/索引。坏页读取、丢页和未知版本明确失败，禁止空覆盖；未知归档版本不得由旧备份降级覆盖。查询结果不进入 snapshot；页面卸载/后台释放明文及输入。

## 备份与改密

外部完整备份继续 v13，单项继续 v1。异步 participant.prepareExport 展开全部页，输出原始完整 messages/version:1，禁止直接导出不含正文的磁盘引用。所有旧 v1–v12 的非 chat 恢复与旧聊天明确丢弃不变。

实际恢复协调器在 prepare 中执行正文准备，再同步 capture；加密恢复日志仍保存自包含的完整原文及原任务状态。补偿还原的是逻辑完整图，可能回到未分片 version:1；不把物理页布局当业务历史。整合测试必须覆盖跨参与者失败、丢页在 journal.prepare 前中止、旧模块不变。完整导出消费临时正文快照，随后清除；会话释放同样清除。

改密逐页用旧密码验证、以新密码写新页，保留所有旧页；现有 repository.reencrypt 将新头的主和 bak 都验证成功后，才切换 Store 密码/图并清理本功能严格 SHA 文件命名空间的旧页及中断遗留页。不是递归删除，不接触旧温馨小家或其他模块。清理失败不能报告改密成功；现有 masterPasswordChangeTransaction 逆序补偿，新头已提交时从新的当前页重写回旧密码。后台失效后不提交迟到明文。

## 容量边界与后续优化

分页和逐页改密不需把全部正文载入内存；首次转换、可移植完整导出、导入解析和恢复协调器的自包含日志仍可能有全图内存峰值。必须分别测量，不能用冷分页 RSS 冒充完整恢复峰值。当前 P7 仍未验收。

下一项内存优化优先保持字节协议：对大字符串逐块调用 CryptoJS 的同一 AES-CBC/PKCS7、OpenSSL MD5 派生和 Salted__+8字节盐/Base64 编码，避免一次生成巨型 WordArray；固定合成盐应与现有 CryptoJS 一次性输出逐字节一致，并覆盖旧读新写/新读旧写、Unicode 边界、错密/坏密文及 JSON 认证后校验。不会顺带替换其他凭据协议或降低恢复门禁。


## 2026-10-30 实测后的有界原生I/O批次设计

Android10k旧候选冷读17.9秒、全导出13.3秒、实际改密90.4秒，逐页原生桥调用是待修复瓶颈。先实现一次readdir元数据核对所有文件的存在/类型/大小；不解密未使用正文，首次读取仍检查ciphertext SHA/解密/字段/索引。目录读取失败、缺页、重复文件信息、大小类型错误继续阻止加载；不提供size的注入驱动严格回到stat而不是接受未知大小。

下一步在不改变50条页格式/写序/加密的前提下，将互不依赖的读/写/删除限制为每批4页。每批必须等待全部settled后才能抛错；失败不启动后续批次，保证没有仍在运行的写任务晚于门禁清理。Store只在全部页验证及owner/revision再检查后提交新头，主/备验证前仍不删除旧页。读取仅用于明确完整导出/回滚capture，不把分页查询扩为全读。改密先并发读旧/写新页，所有副本验证后才严格清理旧命名空间；清理失败继续门禁及原事务补偿。不使用无限Promise.all、后台写队列、强制GC或省略读回验证。

生产测试按不可变候选重新运行，不把本设计当容量通过。不同候选的结果必须保留SHA和失败状态。
